SQLite is enough here: 30 users on one server is a light load, and SQLite in WAL mode handles that easily with the least setup and upkeep. Backup is just copying the file, e.g. with Litestream or the .backup command. Pick PostgreSQL IF any of these apply: more than one app instance or server will write to it; many writes land at the same moment (e.g. everyone clocks in at 9:00 and you see lock waits); other tools like BI or reporting need network access to the database; you need roles, row-level permissions or auditing inside the database; you expect growth to hundreds of users or other apps sharing the data; your team already runs Postgres, so it adds no ops cost. The main question is whether there will ever be more than one app process writing or a second server. If not, use SQLite behind an ORM so you can switch later.
