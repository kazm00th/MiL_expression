Default to SQLite. With 30 users on one server, writes are small and infrequent. Morning clock-in spikes are fine with WAL mode and a busy_timeout. It needs no separate server to run, and a backup is just a copy of the file. Choose PostgreSQL IF any of these apply: you'll run several app processes or servers now or later; many users write at the same moment for long stretches; you need database-level roles, point-in-time recovery or replication; other systems or BI tools will query the database directly; your team already runs Postgres. Either way, access it through an ORM or plain standard SQL so you can switch later without much work.
