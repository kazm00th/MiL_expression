The post overstates and misreads what a "raw logs + retrieval-time summarization beats distillation-into-skills" style result would actually show. Key problems:

1. **False dichotomy / overgeneralization**: "Doubled agent scores on some benchmark(s) with a particular setup" does not license "AI summaries are no longer needed" or "totally obsolete." A single study showing method A beats method B in one setting says nothing about all use cases, all context lengths, all cost budgets, or all tasks. Summarization into SKILLs/docs and raw-log-retrieval-at-use-time are not mutually exclusive either — many real systems combine both (compressed long-term memory + retrieval of specifics).

2. **"No RL needed" is a non-sequitur**: whether summarization happens (and how well) is a separate axis from whether RL/weight updates are used. The study's finding about retrieval-vs-summarization doesn't bear on RL's necessity for other capability improvements (e.g., tool-use policy, reasoning). Conflating these is a category error.

3. **Misrepresents "prior continual-learning work"**: the claim "prior work only said 'current methods plateau, so change the weights'" is a strawman. Continual learning literature is broad — it studies catastrophic forgetting, replay buffers, parameter-efficient adaptation, memory-augmented architectures, etc. Saying it "only said X" and that this new study refutes it by showing "methods can still improve a lot" is a leap: one paper improving one class of methods doesn't invalidate an entire subfield's motivating premise, nor does it show weight-based approaches don't also still have headroom.

4. **Cost/quality tradeoffs ignored**: storing raw logs and summarizing at use time trades storage/retrieval simplicity for potentially higher inference-time cost (re-reading/re-summarizing large context every time), latency, and context-window limits. "Doubled scores" says nothing about whether this is more expensive, slower, or scales to very long histories — where periodic compression into durable artifacts (skills/docs) may still be necessary once raw logs exceed retrievability/context limits.

5. **"Throws away information" is an oversimplification**: good summarization/skill-extraction is supposed to distill *generalizable, reusable* knowledge (procedures, gotchas, decision rules) rather than just compress facts. Raw-log retrieval, if it works better, likely does so because current summarization methods are lossy/poor — a fixable implementation problem — not proof that the whole approach (extracting reusable, generalized knowledge) is conceptually obsolete. Reading the paper's actual claims, benchmarks, and threat-to-validity/limitations sections is needed before drawing such a sweeping conclusion; the post appears to convert a narrow empirical result into a blanket ideological claim ("no RL," "totally obsolete") not supported by the described finding alone.

In short: the post commits overgeneralization from a single result, a false either/or between retrieval and summarization, an unrelated jump to "no RL needed," a strawman of prior continual-learning research, and ignores practical tradeoffs (cost, context limits, scalability) that would determine whether the approach actually replaces summarization in general.
